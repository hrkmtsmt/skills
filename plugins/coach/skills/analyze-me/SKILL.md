# analyze-me

ユーザーが過去に書いたプロンプトを鏡にして、本人が自覚しにくい「考え方のクセ」と「理解の地図」を見せるスキル。
価値は、本人が読んで「確かにそうだ」「それは気づいてなかった」と思える具体性にある。一般論の性格診断にしないこと。全ての主張に、実際のプロンプトの引用と日付を付ける。

## 1. 範囲を決める

ユーザーの言葉から期間とプロジェクトを読み取る。指定がなければ全期間・全プロジェクト。
「直近1ヶ月」なら今日から逆算した `--since`、「このリポジトリだけ」なら `--project` にパスの一部を渡す。

## 2. ダイジェストを作る

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/extract_prompts.py [--since YYYY-MM-DD] [--until YYYY-MM-DD] [--project SUBSTR] --out <scratchpad>/digest.md
```

出力は、統計（月別・プロジェクト別・スラッシュコマンド・タグ件数）と、セッションごと時系列に並べた全プロンプト。
`[Q]` は質問形、`[FIX]` は修正・やり直しの機械的な目印にすぎない。取りこぼしと誤検知の両方があるので、件数をそのまま結論に使わず、本文を読んで判断する。
`:q` や引数なしの `/resume` `/clear` などの操作ノイズは除外済み。トークンらしい長い文字列は `[REDACTED]` に置き換えてある。

ダイジェストは**全文読む**。サンプリングすると「同じことを何度も聞いている」「半年前は質問していたことを今は指示している」といった、このスキルの核心になる時系列のパターンが見えなくなる。
目安として15万字を超える場合は、月ごとに `--since/--until` で分割し、サブエージェントに各期間の観察メモ（下の観点ごとに、引用＋日付付き）を作らせてから統合する。

## 3. 前回のレポートを読む

`~/.claude/analyze-me/reports/` に過去のレポートがあれば最新のものを読む。前回「理解できていない」とした項目が今回どうなったかは、本人にとって最も嬉しい／耳の痛い情報になる。
## 4. 分析の観点

### 思考のクセ
プロンプトの「書き方」と「進め方」から読み取れるパターン。例えば次のとおり。
- 指示の粒度（ゴールだけ渡すか、手順まで指定するか。短い「よろ」「修正して」の多さ）
- 問題への入り方（まず原因を聞く／まず解決策を求める／まず全体像を求める）
- 決め方（選択肢を出させて選ぶ、自分で決めてから確認する、途中で方針を変える）
- 関心の移り方（1セッションで話題が飛ぶか、深掘りし続けるか）
- 自分の言葉で概念を言い換えて確認する頻度、「なぜ」を問う頻度
- 繰り返し使うフレーズや口癖

クセは良し悪しで裁かず、「こういう場面でこう動く傾向がある → だからこういう結果になりやすい」と因果で書く。強みとして働いている面と、裏目に出ている場面の両方を探す。

### 理解できていること
- 自分の言葉で正確に指示している領域（専門用語を正しく使い、具体的な制約を自分で付けている）
- 初期は質問していたが、後期には質問せず指示できるようになった領域（＝学習が進んだ証拠）
- Claudeの提案に対して的確な反論・修正をしている場面（理解していないと出来ない）

### 理解できていないこと・揺らいでいること
次の4つのシグナルを突き合わせる。1つだけのシグナルでは断定しない。
1. **同じ質問の繰り返し** — 同じ概念・コマンド・設定について、別の日・別のセッションで再び聞いている
2. **質問形の語彙** — 「〜って何」「なぜ〜」「どう違う」の対象を分野別に集計する
3. **修正・やり直し** — 「違う」「そうじゃなくて」「戻して」の直前で何を頼んでいたか。意図の言語化が難しかった箇所か、技術的な前提がずれていた箇所かを区別する
4. **学習の進み具合** — 質問がいつまでも減らない領域は、理解が定着していない可能性がある

### 作ると効くスキルの提案
クセと理解の分析を踏まえて、本人の作業を楽にする、またはクセの裏目を補うスキルを1〜4個提案する。次のようなものが候補になる。
- **繰り返している手順**: 別々のセッションで同じ種類の依頼を何度もしている（例: 同じ設定作業、毎回同じ前置きを書いてから頼む）
- **繰り返している確認**: 毎回Claudeに「被る」「公式ドキュメント確認した」と確かめさせている
- **裏目に出ているクセの歯止め**: 例えば「変わらない」ループに入りやすいなら、仮説メモを書かせてから調査を続けるスキル
- **理解が揺らいでいる領域の学習用**: 本人が説明し、Claudeが穴だけを指摘する形式のもの

提案する前に `~/.claude/skills/` と `~/.claude/plugins/` を見て、既にあるスキルと重複しないか確かめる。既存のスキルで足りるのに使われていないなら、新しく作るのではなく「既存の◯◯を使う」と提案する。
形式も選ぶ: 判断が要る手順ならスキル、毎回守ってほしい約束ならCLAUDE.mdやrules、判断の要らない決まった処理ならhook。本人は「決定的なことはプログラムでやりたい」という考え方なので、hookやスクリプトで済むものをスキルにしない。
根拠のない思いつきは出さない。各提案に、何回・いつ同じことが起きたかを引用付きで付ける。

注意: Claudeに作業を「任せている」ことは「理解していない」ことと同じではない。わかっていて委任しているのか、わからないから委任しているのかは、前後のプロンプト（質問の有無、レビュー時の指摘の質）で判断する。根拠が薄いものは「可能性」と明記する。

## 5. レポートを書く

保存先: `~/.claude/analyze-me/reports/YYYY-MM-DD.md`（同日に複数回なら `-2` などを付ける）。初回はディレクトリがないので `mkdir -p ~/.claude/analyze-me/reports` してから書く。
期間やプロジェクトを絞った場合はファイル名に含める（例: `2026-11-13_since-2026-10-01.md`）。

このテンプレートで書く。

```markdown
# 自己分析レポート YYYY-MM-DD

対象: <期間> / <プロジェクト or 全プロジェクト> / <件数>件・<セッション数>セッション

## ひとことで
<この人の現在地を2〜3文で。本人が読んで刺さる具体性で>

## 思考のクセ
### <クセの名前（短く）>
- 傾向: <どんな場面でどう動くか>
- 根拠: 「<引用>」(MM-DD) / 「<引用>」(MM-DD)
- 効いている面 / 裏目に出る面: <因果で>

（3〜6個）

## 理解できていること
| 領域 | 根拠 | 確度 |
|---|---|---|

## 理解できていない・揺らいでいること
### <領域・概念>
- シグナル: <繰り返し / 質問語彙 / 修正 / 学習停滞 のどれか、複数なら全部>
- 根拠: 「<引用>」(MM-DD) …
- 何が欠けていそうか: <概念そのもの / 前提知識 / 用語 / 意図の言語化>
- 確度: <高 / 中 / 低（可能性）>（シグナルの数と期間の長さで決める）

## 学習の推移
<時期ごとに関心と理解がどう動いたか。質問 → 指示 に変わった領域を特に挙げる>

## 前回からの変化
<前回レポートがあれば。なければ省略>

## スキル提案
### <スキル名（kebab-case）>
- 解決すること: <どのクセ・繰り返し・揺らぎを楽にするか>
- 根拠: 「<引用>」(MM-DD) / 「<引用>」(MM-DD)（計<N>回）
- やること: <起動するきっかけと、中でやる手順を2〜3文で>
- 形式: <スキル / CLAUDE.md・rules / hook> と、その形式を選んだ理由
- 既存との関係: <重複する既存スキルがあればその名前と違い。なければ「なし」>

## 次の一歩
1. <具体的で小さい行動。どの概念を、どう確かめるか（1〜3個、効くものだけ）>
```

引用は短く（1文程度）。APIキー、トークン、他人の個人情報は書き写さない。応募先・勤務先の社名、非公開リポジトリ名、社内の固有名詞は「応募先」「業務リポジトリ」のように一般化する。レポートは本人用でも、後で人に見せることがあるため。

## 6. HTMLにして開く

Markdownを書いたら、同じ場所にHTML版を作ってブラウザで開く。読むのはHTML、Markdownは次回の比較用の元データ、という役割分担。

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/render_html.py ~/.claude/analyze-me/reports/<file>.md
open ~/.claude/analyze-me/reports/<file>.html
```

HTMLを手で書かないこと。レンダラーはテンプレートの見出し・箇条書き・表・「確度」をカードやバッジに変換するので、テンプレートの形を崩すと表示も崩れる。

## 7. ユーザーに返す

HTMLのパスを伝え、チャットには「ひとことで」と、特に気づきになりそうな点を2〜3個だけ短く示す。全文をチャットに貼り直さない。
最後に、気になった項目を深掘りできることを一言添える（例: 「◯◯の理解を確かめる質問をしましょうか」）。提案したスキルがあれば、そのうち一番効きそうなものを「作りますか」と聞く。作るときは skill-creator を使う。
